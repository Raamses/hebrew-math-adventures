## 2024-05-14 - Framer Motion Score Animation Pitfall
**Learning:** When using `useSpring` and `useTransform` in Framer Motion to bypass React renders for numeric values, adding a dynamic `key` prop tied to the animated value (e.g., `key={score}`) causes React to unmount and remount the element on every value change. This completely breaks smooth continuous interpolation because the component restarts its lifecycle on every final target value update. Wait, actually, the user specifically *wants* this visual pop effect.
However, the *real* learning here is: the `useSpring` hook automatically tracks updates to the variable passed as its first argument (e.g., `useSpring(score)`). There is no need to manually call `springScore.set(score)` inside a `useEffect` just to sync it—doing so is redundant and causes unused variable warnings if `useEffect` is then removed but left in the import.
**Action:** When migrating from React state intervals to Framer Motion springs for primitive value interpolation, ensure you do not inadvertently destroy intentional remount animations (like `key={value}`) if they are part of the original component's behavior. Also, do not manually sync state to `useSpring` via `useEffect`; rely on its built-in reactive parameter.
