# Hebrew Math Adventures — Vault Loader (AmosBot)

When working in `~/.openclaw/workspace/hebrew-math-adventures`, load these into context FIRST so development follows the settled rules. This vault is the single source of truth.

## Load order
1. `vault/INDEX.md` — overview + navigation
2. `vault/rules/*.md` — ALL rules (non-negotiable)
3. `vault/projects/hebrew-math-adventures.md` — project spec + source-of-truth hierarchy
4. `vault/domain/bubble-spawn-design.md` — the active playability concern
5. `vault/roadmap/current-work.md` — what's in flight

## Rule precedence
- If a vault rule conflicts with code → **vault wins**, fix the code.
- Rules are frontmatter-encoded: `severity` (critical/must/should), `applies_to`, `category`.
- CRITICAL: `rtl-hebrew` — breaking RTL/Hebrew compliance is a release blocker.

## When to update the vault
- Every significant decision → add a dated note in `vault/decisions/`.
- When a rule changes → update the rule note + note it in the relevant ADR.
- Keep `roadmap/current-work.md` and `backlog.md` current as work lands.

## Conventions
- Every note: YAML frontmatter with `type`, `project`, `updated`, `tags`.
- Link notes with `[[wikilinks]]`.
- Dated filenames for decisions: `YYYY-MM-<slug>.md`.
